# CLAUDE.md — Kestrix

## What is this?
Kestrix is a repo-agnostic CI/CD control plane. It uses HCL to define pipelines,
parses trigger conditions via a DAG engine, and dispatches jobs to GitLab runners.

## Tech Stack
- **Language:** Go 1.25 (go.mod), CI uses golang:1.25-alpine
- **HTTP:** Chi router (github.com/go-chi/chi/v5)
- **HCL:** hashicorp/hcl/v2 (manual parsing via hclsyntax)
- **Config:** gopkg.in/yaml.v3 (~/.metaci/config.yaml)
- **Frontend:** React + Vite + MUI + React Flow (ui/)
- **Docs:** Swagger via swaggo/http-swagger at /docs/
- **Testing:** go test with coverage, mock HTTP servers for external APIs

## Build Commands
```bash
make build          # Build binary → bin/metaci
make test           # Run all tests
make quality        # Format check + vet + staticcheck + test + build
make dev            # Run dev server with auto-reload
make fmt-check      # Check formatting only
make vet            # Run go vet
```

## Project Structure
```
cmd/metaci/         # CLI entry point (serve, resolve, validate, variables)
internal/config/    # YAML config loading (~/.metaci/config.yaml)
internal/dag/       # DAG engine + trigger expression parser
internal/dispatch/  # GitLab pipeline dispatch client
internal/model/     # Data model (Project, Task, Repo, Variable)
internal/parser/    # HCL parser (hclsyntax)
internal/store/     # Persistent project config (JSON file)
internal/variables/ # Variable resolution engine
internal/web/       # HTTP server, webhook handler, API, generator
examples/           # Example pipeline definitions (.tf files)
ui/                 # React + MUI frontend
openspec/           # OpenSpec documentation (proposals, specs, tasks)
docs/               # Swagger/OpenAPI (auto-generated by swag)
docker/             # Docker setup (Dockerfile, compose)
```

## Conventions
- **Makefile = source of truth** — never run tools manually
- **Tests before code** (TDD), coverage thresholds
- **Conventional commits** — feat:, fix:, chore:, docs:
- **One logical change per commit**, always push after each
- **gofmt + go vet + staticcheck** must pass in CI
- **No hardcoded paths** in Makefile or build configs
- **Secrets via env vars** — never in code or config committed to repo

## HCL Pipeline Format
```hcl
project "name" {
  ci_repo "repo_name" {
    path = "monorepo/path"  # or url = "https://..."
  }

  ci_task "task_name" {
    trigger    = "repo.repo_name.changed"
    depends_on = ["other_task"]
    repo       = "repo_name"
    script     = "make test"
    image      = "golang:1.26"
  }
}
```

## CI Pipeline
- **Analysis:** gofmt, go vet, staticcheck
- **Test:** go test with coverage
- **Build:** go build with ldflags

## Key Files
- `cmd/metaci/main.go` — CLI entry, config loading
- `internal/web/server.go` — HTTP server, all API handlers
- `internal/web/webhook.go` — Webhook parsing, file classification
- `internal/web/generator.go` — gitlab-ci.yml generation
- `internal/dag/engine.go` — DAG resolution, trigger evaluation
- `internal/dag/expr.go` — Trigger expression parser
- `internal/parser/hcl_parser.go` — HCL → model.Project
- `internal/store/filestore.go` — Persistent JSON project store
- `internal/config/config.go` — YAML config loading
- `internal/dispatch/client.go` — GitLab API client

## Running Tests
```bash
go test ./... -count=1           # All packages
go test ./internal/web/ -v       # Web tests with verbose
go test -run TestWebhook         # Specific test
```

## GitLab Integration
- Webhook: POST /webhook (HMAC-SHA256 or X-Gitlab-Token)
- Dispatch: POST /api/v4/projects/:id/pipeline
- Variables: POST /api/v4/projects/:id/pipelines/:pid/variables
- Config: ~/.metaci/config.yaml or env vars (METACI_*)
