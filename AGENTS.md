# AGENTS.md — Kestrix

## What this is
Repo-agnostic CI/CD control plane. HCL pipelines → DAG trigger resolution → local/Docker/remote-runner execution. Dogfoods itself via `ci/pipeline.tf` + `scripts/`.

## Tech Stack
- **Language:** Go 1.25 (go.mod), CI uses golang:1.25-alpine
- **HTTP:** Chi router (github.com/go-chi/chi/v5)
- **HCL:** hashicorp/hcl/v2 (manual parsing via hclsyntax)
- **Config:** gopkg.in/yaml.v3 (~/.kestrix/config.yaml)
- **Frontend:** React + Vite + MUI + React Flow (ui/)
- **Docs:** Swagger via swaggo/http-swagger at /docs/
- **Testing:** go test with coverage, mock HTTP servers for external APIs

## Version Control (VCS)
- **Prefer `jj` (jujutsu) if available** — use `jj` for all VCS operations: log, diff, bookmark, describe, new, commit.
- **Fallback: `git`** — use when `jj` is not installed or for operations `jj` doesn't support.
- Detection: `command -v jj >/dev/null 2>&1`
- Common `jj` equivalents:
  - `jj log` ↔ `git log`
  - `jj diff` ↔ `git diff`
  - `jj bookmark list` ↔ `git branch -a`
  - `jj bookmark set <name>` ↔ `git checkout -b <name>`
  - `jj describe` ↔ `git commit --amend`
  - `jj new` ↔ create a new working-copy commit
- **Never** mix `jj` and `git` commands in a single logical operation — pick one tool per task.

## Runtime facts agents miss
- **Default runner mode is `local` in config**, but **`runner.allow_local` defaults to `false`** (`KESTRIX_RUNNER_ALLOW_LOCAL=true` is required to opt in). Without `allow_local`, startup, project create/update, and run execution reject `local` mode.
- **DB is PostgreSQL** via `DATABASE_URL` / `--database-url`. PostgreSQL is required for projects, runs, and history.
- **Tests use `KESTRIX_TEST_DATABASE_URL`** (default: `kestrix_test` DB), NOT `DATABASE_URL`. The test helper refuses to connect to any database not ending in `_test`. `make docker-up` auto-creates `kestrix_test` on first init.
- **`handleRunProject` is async**: returns `{run_id, status:"running"}` immediately; work in goroutine. FE polls `GET .../runs/{id}` ~1.5s.
- **Task results are append-only during run** (`pending` → `running` → `passed|failed|skipped`). FE takes **last status per task name**.
- **On failure, runner continues**: dependents → `skipped`; independent tasks still run. Overall status fails if any task failed.
- **`pipeline_def` JSONB** on each run = historical DAG snapshot. Run detail UI must use this, not live pipeline.
- **Scripts need bash** (`pipefail`); busybox `sh` breaks. Pipeline uses `bash scripts/*.sh`.
- **Prod compose**: `docker/docker-compose.prod.yml`, Kestrix (backend + React FE) on **:18080** (dev uses :8080/:3000); the unfinished business site is optional on :8082.
- **Module path**: `kestrix`; repository hosting is configured separately in `project.yaml`.
- **Task processes do not inherit the Kestrix environment.** They see only `PATH`/`HOME`/`LANG`/`LC_ALL`/`TMPDIR`/`TERM`/`USER`, `CI_*`, resolved pipeline variables, and host variables named in `KESTRIX_RUNNER_ENV_PASSTHROUGH` (never `KESTRIX_MASTER_KEY_PATH`, `KESTRIX_JWT_SIGNING_KEY_PATH`, `DATABASE_URL`, `KESTRIX_GITLAB_TOKEN`, `KESTRIX_WEBHOOK_SECRET` - listing one refuses to start). One function, `config.Environment.TaskEnv`, builds this for every executor.
- **`docker` mode is hardened by default**: `--cap-drop ALL`, `--security-opt no-new-privileges`, a PID limit (`KESTRIX_RUNNER_DOCKER_PIDS`, default 256), memory/CPU limits (`KESTRIX_RUNNER_DOCKER_MEMORY`/`_CPUS`, default `2g`/`2`), network `KESTRIX_RUNNER_DOCKER_NETWORK` (default `bridge`; `none` for no egress). No Docker socket mount, no `--privileged`.

## Conventions
- Conventional commits: `feat:`, `fix:`, `chore:`, `docs:`
- One logical change per commit; push when user workflow expects it
- **Every MR/PR must provide a changelog fragment via Changie (`.changes/unreleased/`) before pushing.** Do NOT edit `CHANGELOG.md` directly in feature branches or MRs — Changie aggregates unreleased fragments upon cutting releases to eliminate merge conflicts.
  - Create a fragment with: `make changelog-new KIND=<Added|Changed|Fixed|Deprecated|Removed|Security> BODY="<description>"` (or write a YAML file in `.changes/unreleased/`).
  - Allowed kinds: `Added`, `Changed`, `Fixed`, `Deprecated`, `Removed`, `Security`.
- **Run the changelog gate before creating or updating an MR:** fetch the target branch, then run `make changelog-check TARGET_REF=origin/<target-branch>`. Use `jj git fetch` in jj workspaces. CI blocks MRs missing unreleased fragments unless `[skip changelog]` is in the commit message.
- **Deferred items require an OpenSpec specification in the same MR:** Whenever an issue, review finding (`REVIEW.md`), architectural debt, or feature slice is marked `DEFERRED` (odroczone na przyszłość), it MUST NOT be left as an informal note, forgotten comment, or vague TODO. It MUST receive its own formal OpenSpec proposal/specification (in `openspec/changes/<change-name>/`) within the very same MR in which the decision to defer is made.
- No secrets in repo; env vars (`KESTRIX_*`, `DATABASE_URL`)
- Do not invent Makefile targets — extend Makefile if needed
- FE hooks: never after early returns (Rules of Hooks)
- **Makefile = source of truth** — never run tools manually
- **Tests before code** (TDD), coverage thresholds
- **gofmt + go vet + staticcheck** must pass in CI
- **No hardcoded paths** in Makefile or build configs
- **Secrets via env vars** — never in code or config committed to repo
- **GitLab MR via `glab`** — use `glab mr create` to create merge requests. Never use `curl` for GitLab API. Example:
  ```bash
  glab mr create --source-branch <branch> --target-branch main \
    --title "..." --description "..."
  ```

## Release Workflow & Tagging
- **Prefer CI-driven releases**: Releases and tags should be created using the CI pipeline on `main`:
  - After merging an MR into `main` and confirming the `main` pipeline passed, trigger the manual `create-release-tag` job:
    ```bash
    # Find create-release-tag job ID on main:
    glab api projects/:id/pipelines?ref=main | jq '.[0].id'
    glab api projects/:id/pipelines/<pipeline_id>/jobs | jq '.[] | select(.name=="create-release-tag") | .id'
    # Play the manual release job:
    glab ci play <job_id>
    ```
  - The `create-release-tag` job batches unreleased changelog fragments with Changie, creates the release commit `chore: release vX.Y.Z`, tags `vX.Y.Z`, and pushes to GitLab.
  - The pushed tag triggers the release pipeline (`version-verification`, `publish-image`, `release-binary`, `create-release`).
- **Pre-Release Validation Gate**:
  - NEVER push a release tag without validating version consistency!
  - Always verify that the target tag strictly matches the latest version in `CHANGELOG.md`:
    ```bash
    python3 scripts/verify_version.py --tag <tag_name> --strict
    ```
- **Local release tool (`scripts/release.py` / `make release-push`) & Jujutsu (`jj`)**:
  - When running releases locally:
    - In colocated `jj` repos, `git tag` must target the explicit commit SHA (`jj log -r @ -T commit_id --no-graph`), never default `git HEAD` (which does not advance on `jj describe` until export).
    - `scripts/release.py` runs `scripts/verify_version.py --tag <tag> --strict` before pushing to guarantee the tag points to the commit with the updated `CHANGELOG.md`.

## GitLab Integration
- Webhook: POST /webhook (HMAC-SHA256 or X-Gitlab-Token)
- Dispatch: POST /api/v4/projects/:id/pipeline
- Variables: POST /api/v4/projects/:id/pipelines/:pid/variables
- Config: ~/.kestrix/config.yaml or env vars (KESTRIX_* only)

## Cancel runs
`POST /api/projects/{name}/runs/{id}/cancel` → `RunService.Cancel`:
- Active run (registered in `RunService.active`/`.done`): cancels its context, sends the task's process group SIGTERM then SIGKILL (`local`)/`docker stop` (`docker`) after `KESTRIX_RUNNER_CANCEL_GRACE` (default 10s), waits up to grace+5s, then the store marks it `canceled`.
- No active entry (already finished, waiting for manual approval, or from before a restart): falls back to `PGStore.CancelRun` (status-only rewrite): `running`→`canceled`, `pending` without incomplete deps→`canceled`, `pending` depending on incomplete/failed→`skipped`, `passed` unchanged.
- Wait times out (process didn't die within grace+5s): `504`, run stays `running` — never falsely reported `canceled`.

## API Field Naming Convention
- **Backend (Go)**: JSON responses use lowercase field names (Go convention: `json:"repos"`, `json:"tasks"`, `json:"default_image"`)
- **Frontend (JS)**: React Flow layout (`dagLayout.js`) expects capitalized property names (`Repos`, `Tasks`, `Name`, `Path`, `Kind`, `DefaultImage`)
- **Normalization**: Happens in `ui/src/api/normalizers.js` (re-exported by `ui/src/api/client.js`) via `normalizeProject()` helper
  - Applied in: `getProjectDefinition()`, `getProject()`, `listProjects()`
  - Maps lowercase → capitalized for top-level and nested fields (e.g., `execute.script` → `Execute.Script`)
