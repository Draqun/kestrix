# AGENTS.md — Kestrix

## What this is
Repo-agnostic CI/CD control plane. HCL pipelines → DAG trigger resolution → local/Docker/GitLab-runner execution. Dogfoods itself via `ci/pipeline.tf` + `scripts/`.

## Tech Stack
- **Language:** Go 1.25 (go.mod), CI uses golang:1.25-alpine
- **HTTP:** Chi router (github.com/go-chi/chi/v5)
- **HCL:** hashicorp/hcl/v2 (manual parsing via hclsyntax)
- **Config:** gopkg.in/yaml.v3 (~/.kestrix/config.yaml)
- **Frontend:** React + Vite + MUI + React Flow (ui/)
- **Docs:** Swagger via swaggo/http-swagger at /docs/
- **Testing:** go test with coverage, mock HTTP servers for external APIs

## Version Control (VCS)
- **Prefer `jj` (jujutsu) if available** — use `jj` for all VCS operations: log, diff, bookmark, describe, new, commit.
- **Fallback: `git`** — use when `jj` is not installed or for operations `jj` doesn't support.
- Detection: `command -v jj >/dev/null 2>&1`
- Common `jj` equivalents:
  - `jj log` ↔ `git log`
  - `jj diff` ↔ `git diff`
  - `jj bookmark list` ↔ `git branch -a`
  - `jj bookmark set <name>` ↔ `git checkout -b <name>`
  - `jj describe` ↔ `git commit --amend`
  - `jj new` ↔ create a new working-copy commit
- **Never** mix `jj` and `git` commands in a single logical operation — pick one tool per task.

## Runtime facts agents miss
- **Default runner mode is `local`** (host bash), not Docker. Config: `Runner.Mode` / env.
- **DB is PostgreSQL** via `DATABASE_URL` / `--database-url`. Runs/history need PG; file store has no runs.
- **Tests use `METACI_TEST_DATABASE_URL`** (default: `metaci_test` DB), NOT `DATABASE_URL`. The test helper refuses to connect to any database not ending in `_test`. `make docker-up` auto-creates `metaci_test` on first init.
- **`handleRunProject` is async**: returns `{run_id, status:"running"}` immediately; work in goroutine. FE polls `GET .../runs/{id}` ~1.5s.
- **Task results are append-only during run** (`pending` → `running` → `passed|failed|skipped`). FE takes **last status per task name**.
- **On failure, runner continues**: dependents → `skipped`; independent tasks still run. Overall status fails if any task failed.
- **`pipeline_def` JSONB** on each run = historical DAG snapshot. Run detail UI must use this, not live pipeline.
- **Scripts need bash** (`pipefail`); busybox `sh` breaks. Pipeline uses `bash scripts/*.sh`.
- **Prod compose**: `docker/docker-compose.prod.yml`, Kestrix on **:8081** (dev often :8080).
- **Module path**: `kestrix`; repository hosting is configured separately in `project.yaml`.

## Conventions
- Conventional commits: `feat:`, `fix:`, `chore:`, `docs:`
- One logical change per commit; push when user workflow expects it
- No secrets in repo; env vars (`METACI_*`, `DATABASE_URL`)
- Do not invent Makefile targets — extend Makefile if needed
- FE hooks: never after early returns (Rules of Hooks)
- **Makefile = source of truth** — never run tools manually
- **Tests before code** (TDD), coverage thresholds
- **gofmt + go vet + staticcheck** must pass in CI
- **No hardcoded paths** in Makefile or build configs
- **Secrets via env vars** — never in code or config committed to repo
- **GitLab MR via `glab`** — use `glab mr create` to create merge requests. Never use `curl` for GitLab API. Example:
  ```bash
  glab mr create --source-branch <branch> --target-branch main \
    --title "..." --description "..."
  ```

## HCL Pipeline Format
```hcl
project "name" {
  ci_repo "repo_name" {
    path = "monorepo/path"  # or url = "https://..."
  }

  ci_task "task_name" {
    trigger    = "repo.repo_name.changed"
    depends_on = ["other_task"]
    repo       = "repo_name"
    script     = "make test"
    image      = "golang:1.26"
  }
}
```

## GitLab Integration
- Webhook: POST /webhook (HMAC-SHA256 or X-Gitlab-Token)
- Dispatch: POST /api/v4/projects/:id/pipeline
- Variables: POST /api/v4/projects/:id/pipelines/:pid/variables
- Config: ~/.kestrix/config.yaml or env vars (METACI_*)

## Cancel runs
`POST /api/projects/{name}/runs/{id}/cancel` → `PGStore.CancelRun`:
- `running` → `canceled`
- `pending` without incomplete deps → `canceled`
- `pending` depending on incomplete/failed → `skipped`
- `passed` unchanged  
Does **not** kill OS processes yet (status-only); stuck runs still need cancel to leave `running`.

## UI notes

- Layout drawer is persistent; main content must **not** double-apply `ml: 260` if flex already accounts for drawer — check `Layout.jsx` before changing margins

## API Field Naming Convention
- **Backend (Go)**: JSON responses use lowercase field names (Go convention: `json:"repos"`, `json:"tasks"`, `json:"default_image"`)
- **Frontend (JS)**: React Flow layout (`dagLayout.js`) expects capitalized property names (`Repos`, `Tasks`, `Name`, `Path`, `Kind`, `DefaultImage`)
- **Normalization**: Happens in `ui/src/api/client.js` via `normalizeProject()` helper
  - Applied in: `getProjectDefinition()`, `getProject()`, `listProjects()`
  - Maps lowercase → capitalized for top-level and nested fields (e.g., `execute.script` → `Execute.Script`)
