## Why

We need a living overview of which OpenSpec specs have been fully implemented in code, which are partially done, and which haven't been started. This helps prioritize work and prevents regressions.

## What Changes

- Creates a tracking change (`spec-implementation-audit`) in the OpenSpec changes directory
- Each spec is represented as a task group with checkboxes for its requirements
- The checklist is updated as implementation progresses
